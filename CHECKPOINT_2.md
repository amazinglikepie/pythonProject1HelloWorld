## 2. Cross-check against the Qiu tracker (your requirement 3)

Matching by normalised product name; comparison on the last date the Qiu tracker carried each product, using
modelpricewatch's latest point on or before that date.

| Result | Count |
|---|---|
| Agree, vendor's own price | 27 |
| **Disagree, vendor's own price** | **3** |
| Agree, US-host resale row (expected to differ from vendor price) | 9 |
| Disagree, US-host resale row (expected) | 8 |
| Qiu product not present in modelpricewatch | 10 |
| modelpricewatch had no point yet on the comparison date | 7 |

The three substantive disagreements:

1. **MiniMax-M2.5, 2026-05-19.** Qiu 2.1 / 8.4; modelpricewatch 0.3 / 1.2. Both ratios are exactly 7.0
   (2.1 / 0.3 = 7.0; 8.4 / 1.2 = 7.0), which is the CNY-per-USD rate. The Qiu figure is consistent with a
   mainland-China yuan price recorded as dollars; the Qiu author's own note says older MiniMax CNY points were
   omitted from the chart line. Consequence: the Qiu "price change" for MiniMax-M3 on 2026-08-17
   (2.1, 8.4 to 0.3, 1.2) is probably a currency relabel, not a price cut. Unverified from here; MiniMax's
   domestic pricing page would settle it.
2. **GPT-5.6 Sol, 2026-09-12.** Qiu 5.0 / 30.0 (source: developers.openai.com pricing page);
   modelpricewatch 4.0 / 20.0 (daily snapshot). Unresolved. Needs the official page.
3. **Qwen3.7-Max, 2026-09-12.** Qiu 1.25 / 3.75 labelled "50% promo"; modelpricewatch 2.5 / 7.5 list price.
   Not a contradiction: promotional versus list. Your brief asks for list prices; a promo series would be a
   sensitivity check. The modelpricewatch changelog entry dated 2026-09-11 ("Qwen3.7-Max $1.25 to $2.00") is for
   the Together-hosted row, not Alibaba's own.

Date resolution: where both sources record the same change, modelpricewatch's own-capture date precedes the
Qiu curation date (GPT-5.6 Terra and Luna cuts: 2026-08-01 "verified" versus 2026-08-17; DeepSeek V4 Pro increase:
2026-08-16 versus a new Qiu row on 2026-08-17). For event dating inside the 79-day window, modelpricewatch is the
better of the two.

## 3. Can the reconstructed points be verified?

Each `litellm-archive` point carries the LiteLLM commit hash it was read from. Test: the Jamba Large point
(2025-07-21, 2.0 / 8.0, sha 41436fefa0) was checked by fetching
`https://raw.githubusercontent.com/BerriAI/litellm/41436fefa0/model_prices_and_context_window.json`
(HTTP 200, 604,318 bytes): the file lists jamba-large at 2e-06 / 8e-06 per token = $2 / $8 per million. Match.
The commit's date could not be read from GitHub's web endpoints (403) but can be obtained with a shallow git fetch
of that hash if needed. So the reconstruction is checkable point by point.

## 5. Decisions needed

1. **History depth.** The only reachable route to multi-year dated prices is the LiteLLM catalog's git history on
   GitHub (`BerriAI/litellm`, file `model_prices_and_context_window.json`), which is exactly what modelpricewatch
   reconstructs its pre-June-2026 points from. It is a community-maintained catalog, not official pages: entries lag
   provider announcements by days to weeks and occasionally contain errors, and every point would be tied to a commit
   hash and date. Using it directly is a substitution and needs your approval. Alternative: run the study on the
   79-day dual-source window only, which supports a cross-section and short-window analysis but not the 12-month trend.
2. **Capability scores.** Simplest route: for the pair candidates, read each model's Intelligence Index off its
   public Artificial Analysis model page and type it into a table with the page URL and date. I will supply the list.
3. **GPT-5.6 Sol.** Read the input and output price off OpenAI's pricing page to resolve disagreement 2.
4. **FX.** Upload the FRED CSV.
